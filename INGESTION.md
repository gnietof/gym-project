# Ingestion

This file describes the steps required to ingest all the information in the database. 
This application uses mainly two tables: activities and sessions. Activities stores information about all the different activities while sessions keeps a list of when those activities are scheduled in the Gym.

## Changes in V2.0 
The structure of the tables in the database has slightly changed in V2.0. 
Initially, all the information about the activities was stored in one single table which included all the data and also the 'full_activity' column and the embeddings. The full_activity was a merge of all the semantically searchable information. This information had been embedded and stored in the same table.

In V2.0, the activities table only keeps information about the activities (including some fields which initially where only present in the full_activity column.
The 'full_activity' and the embedding columns have been moved to a different table.

### Plan for V2.1
The 'usages' table keeps track of all the information sent to the LLM's. This table includes lots of information. It also includes the scores being provided by the users to each of the AI assistant responses and the number of tokens used in each request.
In V2.1 the scores and the tokens will also be moved to different tables. While the 'usages' is basically a log, 'scores' and 'token' are used to build the dashboards so they will be accessed more frequently. This separation will improve performance.

## Initial Load

All the information comes initially from three JSON files (all of them in [resources/](resources/)).

| File | Description |
| - | - |
| GymActivities | All information related to each of the activities. This file was generated by ChatGPT. |
| activities | Specific information for each of those activities in the gym such as duration. |
| sessions | Initial schedule of each of the sessions. |

### Ingestion process

All the steps required to create the tables and insert the required information are executed by a single Python script: [load.py](init/load.py). This script executes a set of actions which combine pure SQL commands mixed with some Python code.

The included steps are detailed below:

1. All the required schemas, required tables (activities, sessions, impacts ...) as well as a few temporary tables are created in the database using the SQL script [create.sql](init/create.sql).
The temporary tables being created are:
-  All the information in GymActivities loaded in table tmp_descriptions.
-  All the information in activities loaded in table tmp_activities.
-  All the information in sessions loaded in table tmp_sessions.
Tables tmp_activities and tmp_sessions are related by a code which was made up when the initial schedule was encoded in an JSON file.
Tables tmp_descriptions and tmp_activities are related by the activity_name.

2. Python code in [load.py](init/load.py) is used to ingest these JSON files into the tables.
3. For intensity, impact, skills and caloric burns table contents are generated using [init.sql](init/init.sql). Each of the values found in GymActivities have been included.
Category and subcategories tables are filled with unique values in the tmp_descriptions using the same SQL script.
4. The final activities table is filled using the information from tmp_descriptions using [fill.sql](init/fill.sql).  
4.1. Activities
  - Each category and subcategory is converted into a code (matching the related tables).
  - Each intensity, impact, skill and caloric burn is converted into a code (matching the related tables).
  - An activity_code is added from the tmp_activities table.
4.2. Embeddings
The embeddings table is also created in this step using information from the description of each activity. Several columns are merged into a 'description'.
4.3. Sessions
The sessions table is filled with the code of the activity, dow (sunday to saturday), day (sunday = 0 to saturday = 6), the start time and the duration.
5. The embeddings which was created in a previous step is now being added the embeddings for each of the generated 'descrptions'. 
The Python script is used to loop through each description and obtaining the embeddings.
6. The prompts are added to the database. These is a collection of default prompts which are required for each tool and the agent itself. The SQL script in [prompts.sql](init/prompts.sql) is executed.

7. Finally, there is another script [questions.sql](init/questions.sql) which creates (and fills) the table with test questions.
